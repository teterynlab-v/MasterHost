# M0 World image persistence — 2026-09-21

World-level custom images are named attachments to the materialized World. The authoritative World JSON stores the name, media type, byte count, and SHA-256 digest; PostgreSQL stores immutable image bytes by digest. Upload updates the World and its revision record in one transaction. Snapshot/restore and fork retain or restore the World image references; regeneration carries them forward. Existing revisions remain readable and old bytes remain available for snapshots. A stale World authoring save returns 409 instead of overwriting a concurrent image revision.

The `.mhworld` ZIP includes referenced image files under `assets/` and SHA-256 entries in `checksums.json`. Import verifies metadata, checksum and image signature, assigns an independent World ID, and commits blobs, World and initial revision together. Export reads only referenced images and verifies stored digests. An incomplete or mismatched image set fails closed. The upload API accepts PNG, JPEG and WebP by signature, with a 2 MB per-image and 20-image per-World limit; the browser can upload and download these images. The original Pack's built-in assets are separate from user World attachments.

An entity may assign a World image to an `AssetSet` role (portrait, token, card, background, map, item, location or ui). Its reference stores the image name and checksum; repository saves and ZIP export/import reject missing or mismatched references. Assign/remove creates a World revision, and regeneration carries roles for entities with a stable materialization path. Snapshot restore, fork and import preserve role references. The same-name image cannot be replaced with different bytes while any entity references it; detach those roles first. The image read endpoint serves `inline` only for the browser thumbnail request, and otherwise downloads the file.

Fantasy and Cyberpunk live PostgreSQL smokes covered invalid uploads, role assignment, conflicting replacement rejection, byte readback, snapshot restore, regeneration, fork, ZIP import and detachment. A stale authoring save was rejected after an image upload. The Fantasy browser attached a portrait to an entity, displayed the thumbnail at its natural dimensions, and retained it after reload. The full 55-test suite, TypeScript check and web build passed. Blobs are currently retained after a World stops referencing them, so garbage collection and storage quotas beyond the per-World limit remain operational work. These checks used an existing local PostgreSQL database; the full M0 clean-database/manual checklist remains open.
