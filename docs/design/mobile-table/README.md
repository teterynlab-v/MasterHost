# MasterHost: мобильный стол — предложение дизайнера

Статус: интерактивный макет на согласование. Production-код и desktop-дизайн не изменены.

## Задача

На телефоне мастер ведёт игру без обязательного ожидания участников; игрок видит карту, персонажа и доступный бросок. Переключение между задачами занимает одно нажатие, карта не теряется в длинной колонке desktop-панелей.

## Решение

- Мастер: вкладки «Карта», «Сцены», «Группа», «Журнал»; приглашение и исключение участника в нижней панели с подтверждением.
- Игрок: «Карта», «Персонаж», «Действия», «Журнал»; назначенная проверка и кубик постоянно над нижней навигацией.
- Отдельная мобильная компоновка для 360–430 px, общей модели данных и игрового движка. Это веб-приложение с мобильными паттернами, не отдельная iOS/Android программа.
- Нижние панели ограничены высотой телефона, прокручиваются внутри и удерживают фокус через стандартный dialog.
- Завершение сессии показывает сохранение мира и возможность новой сессии мастеру. Игроку не показывается мастерская кнопка.
- При потере соединения карта и персонаж остаются видны. Обновление вкладки должно восстановить тот же стол, а не создать мир заново.
- Нулевой ресурс показан отдельно от остальных ресурсов. Это иллюстрация: актуальные эффекты определяет Pack; макет не доказывает исправление игрового бага.

## Открыть

`index.html` работает автономно без зависимостей и запросов к API.

Для просмотра через локальный сервер:

```sh
python3 -m http.server 8399 --bind 127.0.0.1 --directory /Users/viktarteteryn/.codex/visualizations/2026/10/04/masterhost-mobile
```

- Все варианты: `http://127.0.0.1:8399/`
- Мастер: `http://127.0.0.1:8399/?phone=1&role=gm`
- Игрок: `http://127.0.0.1:8399/?phone=1&role=player`
- Персонаж: `http://127.0.0.1:8399/?phone=1&role=player&tab=character`
- Переподключение: `http://127.0.0.1:8399/?phone=1&role=player&state=reconnecting`
- Завершение: `http://127.0.0.1:8399/?phone=1&role=gm&state=ended`

## Проверено

CUA / in-app browser: viewport 360, 390, 430 × 844; горизонтального переполнения нет. Видимые кнопки карты, панели, кубика и навигации — минимум 48 px (навигация 62 px). Проверены вкладка персонажа, панель игроков, состояние переподключения с недоступным кубиком, завершённая сессия. Снимки PNG рядом с HTML.

Открыто перед реализацией: утверждение пользователя; проверка на реальном iOS/Android устройстве, появление клавиатуры, жесты и зум реальной карты, длинные переводы, работа screen reader. Реальные значения, броски, состояние присутствия и сохранения в этом макете демонстрационные.

## Альбомная ориентация

Карта в центре, компактная навигация слева. Справа у мастера контекст сцены, у игрока краткая карточка персонажа; кубик закреплён под правой панелью. Карточка, сцена и группа открываются в боковой панели с внутренней прокруткой.

Переключатели макета: «Портрет», «Альбом», «По экрану». При автоматическом повороте роль, вкладка, состояние сессии и открытый диалог не сбрасываются. Широкий экран высотой до 540 px включает альбомную компоновку.

Размеры областей нажатия: минимум 48 px в портрете и 44 px в альбомной ориентации.

Проверено через CUA/Chrome: 844×390 и 740×360; размеры страницы равны viewport, горизонтального/вертикального переполнения страницы нет. Открытая панель «Игроки» сохраняется при повороте 844×390 → 390×844 → 740×360, перестраивается из боковой в нижнюю и обратно. На 740×360 области нажатия фигурок карты — 47.96 px.

Снимки: `gm-landscape.png`, `gm-landscape-players.png`, `player-landscape.png`, `player-landscape-740.png`, `player-landscape-character.png`.

В полном макете «Альбом» показывает рамку 844×390. Для реального поворота используйте `?phone=1&role=gm` или `?phone=1&role=player` при соответствующем viewport; перезагрузка и новый URL не требуются.

Это макеты. Реальное устройство, экранная клавиатура, длинные переводы, screen reader и игровая интеграция пока не проверены. Игровые данные демонстрационные; дополнительных правил этот дизайн не вводит.
